# MBTI 검증 딥리서치 에이전트 — 프로젝트 계획서

> **한 줄 요약** — "MBTI 궁합론은 근거가 있는가"를 영문 위키백과 52건에서 스스로 조사해 한국어 보고서로 써 오는 멀티 에이전트를 만들고, 그 협업 과정을 아이소메트릭 연구소에서 캐릭터가 움직이는 모습으로 실시간 시각화해 배포한다.

## 1. 개요

### 1.1 만드는 것

| 층 | 산출물 |
|---|---|
| **파이프라인** | LangGraph 6노드 — 코디네이터 1명이 조사관 4명을 병렬 파견하는 딥리서처 |
| **시각화** | 의존성 0 · Canvas 아이소메트릭 연구소. 조사관이 서고를 오가며 일하는 모습 |
| **배포** | Vercel. 기본은 녹화 재생(키 불필요), 옵션은 방문자 본인 키로 라이브 실행 |

### 1.2 왜 이 주제인가

MBTI 궁합론은 **대중적으로 널리 믿기지만 학술적 근거가 빈약한** 주제다. 이 파이프라인의 핵심 장치가 **"문장마다 «문서명» 근거 붙이기"**이므로, 주제 자체가 그 장치의 의미를 증폭시킨다.

> 질문: **"MBTI 궁합론은 어떤 근거로 제시되며, 심리학계는 이를 어떻게 평가하는가?"**

보고서는 한국어로 쓰되 코퍼스는 영문이다. 원문 언어 ≠ 산출물 언어라는 점도 이 구조가 감당할 수 있음을 보여주는 사례가 된다.

## 2. 주제와 코퍼스 — 실측 근거

### 2.1 코퍼스가 통과해야 할 4조건 (강의 근거)

| 조건 | 왜 필요한가 | 어기면 |
|---|---|---|
| ① 답이 여러 문서에 흩어져 있을 것 | 한 문서로 끝나면 나눌 일이 없다 | 조사관 넷 중 셋이 헛읽는다 (16강 Q1) |
| ② 문서가 길 것 | 짧으면 컨텍스트 격리가 무의미 | 이 구조를 쓸 이유 자체가 사라진다 |
| ③ 문서끼리 링크로 이어질 것 | 프런티어 탐색의 생명줄 | "읽은 내용이 다음 선택을 만든다"가 죽는다 (9강) |
| ④ 절이 자연스럽게 나뉠 것 | 나눌 것이 실제로 나뉘어 있어야 한다 | 넷이 같은 문서를 네 번 읽는다 (5강) |

### 2.2 후보 3안 실측 비교

| | 한국어 MBTI | 한국어 심리학 | **영문 심리학 (채택)** | 원본(근대사) |
|---|---|---|---|---|
| 문서 수 | 10건 | 19건 | **52건** | 34건 |
| 총 본문 글자 | 199,369 | 587,861 | **1,705,434** | 447,487 |
| 평균 길이 | 19,936 | 30,940 | **32,797** | 13,161 |
| 내부 링크 | — | 48개 | **485개** | 428개 |
| 문서당 링크 | — | 2.5 | **9.3** | 12.6 |
| 고립 문서 | — | 1건 | **1건** | 1건 |
| 판정 | ❌ 16유형이 전부 리다이렉트 | ❌ 링크가 원본의 1/5 | **✅ 전 조건 통과** | 기준 |

**탈락 사유 기록**

- **한국어 MBTI**: 16개 유형(INFP…ESTJ) 문서가 **전부 「MBTI」 하나로 리다이렉트**. 조사관 넷이 같은 문서 하나를 읽게 되어 조건 ①③이 동시에 무너진다.
- **한국어 심리학**: 분량(587K)은 충분하나 `빅 파이브`(1K)·`한스 아이젠크`(1K)·`신뢰도`(2K)·`심리측정학`(4K) 등 **비판의 핵심 근거가 토막글**. 링크 밀도 2.5는 프런티어가 두세 번에 막힌다.

### 2.3 채택 코퍼스 상세

```
출처   en.wikipedia.org
문서   52건 · 1,705,434자 · 평균 32,797자
링크   485개 (문서당 9.3)
토큰   약 852,700 — gpt-4o-mini 창(128,000)의 6.7배
```

**컨텍스트 창의 6.7배**라는 점이 중요하다. 원본 근대사 코퍼스는 1.7배였으므로, "혼자서는 물리적으로 불가능하다"는 전제가 원본보다 4배 선명하다.

### 2.4 서고(분류) 구성

| 서고 | 건수 | 대표 문서 |
|---|---|---|
| 측정 | 11건 | Psychometrics, Reliability, Replication crisis(101K), Factor analysis(77K) |
| 유형론 | 11건 | Carl Jung(96K), MBTI(37K), Enneagram, Socionics, Psychological Types |
| 성격심리 | 11건 | Big Five(91K), Trait theory, Hans Eysenck, Raymond Cattell, 16PF |
| 유사사례 | 7건 | Pseudoscience(47K), Astrology, Blood type personality theory, Phrenology |
| 편향 | 6건 | Barnum effect, Confirmation bias(58K), Self-fulfilling prophecy |
| 관계 | 6건 | Interpersonal attraction, Assortative mating, Social psychology |

이 분류는 시각화의 **서고 배치와 1:1로 대응**한다. 조사관이 어느 서고로 걸어가는지가 곧 배정 로그가 된다.

### 2.5 고립 문서 — 버그가 아니라 자산

`Assortative mating`(유유상종 짝짓기)은 **어떤 문서도 링크하지 않는다.** 원본의 «거문도 사건»과 정확히 같은 위치다.

그런데 이 문서는 주제상 **"사람들이 실제로 비슷한 상대와 맺어지는가"**라는, 궁합론 검증의 핵심 근거다. 즉:

> **링크로는 절대 닿을 수 없는데, 질문에는 꼭 필요한 문서.**

4강에서 고른 "카드(제목 + 앞 250자)" 결정이 값을 하는지를 검증할 자리가 공짜로 생겼다. 카드를 끄면 이 문서에 아무도 닿지 못하고, 그 사실이 보고서에서 드러나야 한다.

### 3.2 이벤트 스트림 분리 (핵심 원칙)

`agent-office` 프로젝트의 설계 원칙을 **개념만** 가져온다. 코드는 새로 짠다.

```
 [이벤트 소스]          [번역/연출]         [월드 상태]        [렌더러]
 무슨 일이 있었나   →   어떻게 보여줄까   →   지금 상태     →   화면
 ──────────────      ─────────────      ──────────      ────────
 재생: runs/*.json    Choreographer      World            Canvas
 라이브: SSE          (프런트)           (agents/sections) (아이소메트릭)
```

**백엔드는 "조사관이 어느 서고로 걸어가야 하는지" 몰라도 된다.** 그 번역은 전적으로 프런트 Choreographer의 몫. 이 경계가 흐려지면 나중에 절제 실험 스위치를 넣을 때 백엔드를 다시 뜯게 된다.

### 3.3 두 가지 실행 모드

| | 재생 모드 (기본) | 라이브 모드 (옵션) |

## 4. 이벤트 프로토콜 (프런트/백 사이의 유일한 계약)

모든 이벤트는 `{ v, type, ts, ...payload }` 형태.

### 4.1 의미 이벤트 (백엔드 → 프런트)

```jsonc
{ "v":1, "type":"run.start",        "question":"MBTI 궁합론은…", "설정":{"절수":4,"절예산":3,"배정":true,"구역":true,"역할":true,"재위임":true} }
{ "v":1, "type":"plan.done",        "목차":[{"절":"융의 유형론","역할":"큰그림 담당","시작문서":"Carl Jung","서고":"유형론"}, …] }
{ "v":1, "type":"dispatch",         "바퀴":1, "인원":4, "배치":[0,1,2,3] }
{ "v":1, "type":"researcher.start", "절":"융의 유형론", "역할":"큰그림 담당", "시작문서":"Carl Jung", "피하기":["Psychometrics", …] }
{ "v":1, "type":"researcher.read",  "절":"융의 유형론", "문서":"Carl Jung", "서고":"유형론", "원문자수":96523, "메모자수":412, "관련":true }
{ "v":1, "type":"researcher.done",  "절":"융의 유형론", "자수":631, "인용":9, "충분":true, "부족":"" }
{ "v":1, "type":"researcher.fix",  "절":"융의 유형론", "허위":["16PF Questionnaire"], "남은허위":[], "채택":true }
{ "v":1, "type":"review",           "절수":4, "빈칸":["청일…"], "종료":null }
{ "v":1, "type":"synthesize",       "절수":4, "보고서자수":2796 }
{ "v":1, "type":"evaluate",         "metrics":{ … } }
{ "v":1, "type":"run.end" }
```

`researcher.read`에 **원문자수와 메모자수를 함께** 싣는 것이 핵심이다. 화면에서 "두꺼운 책 → 얇은 메모"로 **컨텍스트 격리가 그대로 보인다**.

`researcher.fix`는 **허위 인용을 잡아 다시 쓰게 한 순간**이다. 12편 중 5편에만 나온다(`채택:false`면 고쳐 온 원고가 더 나쁘라 버렸다는 뜻). **조건부로만 나오는 유일한 이벤트**이므로, 재생기는 이 타입이 없는 녹화도 그대로 재생해야 한다.

### 4.2 번역 규칙 (의미 → 연출)

| 의미 이벤트 | Choreographer 동작 |
|---|---|
| `plan.done` | 소장이 화이트보드로 이동 → 절 카드 4장 부착 → `say:"넷으로 나눕니다"` |
| `dispatch` | 조사관 4명이 **동시에** 각자 배정 서고로 출발 (팬아웃이 눈에 보이는 순간) |
| `researcher.read` | 서고에서 책 꺼내는 모션 → 머리 위에 `원문자수` 두께의 책 → 나올 때 `메모자수` 크기 쪽지로 축소 |
| `researcher.read(관련:false)` | 책을 덮고 `say:"관련 없음"` → 빈손 |
| `researcher.done(인용:0)` | **빨간 테두리** + `say:"근거를 못 찾았어요"` |
| `review(빈칸 있음)` | 해당 조사관에게 빨간 딱지 → 서고로 **되돌아가는** 애니메이션 |
| `evaluate` | 계기판 7개 숫자가 하나씩 채워짐 |

### 4.3 연출 명령 (프런트 내부 생성 — 백엔드는 모름)

```jsonc
{ "type":"move",   "agentId":"r1", "to":[7,3] }
{ "type":"status", "agentId":"r1", "status":"reading" }
{ "type":"say",    "agentId":"r1", "text":"Carl Jung 읽는 중… 📖", "duration":3 }
{ "type":"carry",  "agentId":"r1", "size":"book" | "memo" | "none" }
```

## 5. 시각화 설계

### 5.1 연구소 레이아웃

```
┌──────────────────────────────────────────────────────────┐
│  📋 화이트보드(목차)      📚 유형론    📚 성격심리          │
│                                                           │
│  🪑 ① 소장 책상           📚 측정      📚 편향             │
│                                                           │
│  🔍 ④ 검토 테이블         📚 유사사례   📚 관계            │
│                                                           │
│  🖨️ ⑤ 조판대   📊 ⑥ 계기판    🪑🪑🪑🪑 조사관 책상        │
└──────────────────────────────────────────────────────────┘
```

### 5.2 등장인물

| ID | 역할 | 화면에서 하는 일 |
|---|---|---|
| `coord` | 소장 (코디네이터) | 화이트보드에 목차 부착 → 검토 테이블에서 빈 칸 점검 → 조판대에서 머리말 작성 |
| `r1`~`r4` | 조사관 | 배정 서고로 이동 → 책 읽기 → 링크 타고 다음 서고 → 자기 책상에서 원고 집필 |

역할(`큰그림/시간순/인물/원인/비교 담당`)은 캐릭터 색과 이름표로만 구분한다.

> **화면 문구 제약 (14.4 실측)** — 17강은 역할에 효과가 없다고 했고, 우리 12편도 역할을 켜서 좋아졌다는 증거를 주지 못했다. 그러나 각 칸이 1회 실행이라 **"역할은 효과가 없다"고 화면에 단정할 수 없다.** 쓸 수 있는 문장은 "이 실행들에서는 역할을 켠 쪽이 더 낫지 않았다"까지다. 단정하려면 칸당 3회 반복(₩1,100 · 15분)이 먼저다.

### 5.3 시각화가 드러내는 강의 개념

| 강의 개념 | 화면에서 보이는 것 |
|---|---|
| 팬아웃 (Send) | 배치 순간 4명이 **동시에** 흩어진다 |
| 구역 분할 (피하기) | 각자 **다른 서고**로 간다. 끄면 한 서고에 몰린다 |
| 컨텍스트 격리 5% | 두꺼운 책 → 얇은 메모 |
| 재위임 루프 | 빨간 딱지 → **되돌아가는** 애니메이션 |
| 인용 0곳 절 | 빈손으로 돌아온 조사관 |
| 고립 문서 | `Assortative mating` 서가는 **링크로는 닿을 수 없다**. 배정이 직접 보내야만 간다 |
| 허위 인용 교정 | `researcher.fix` — 빨간 딱지를 받고 **원고를 고쳐 쓴다** (12편 중 5편) |

### 5.4 에셋 — 전부 Kenney · CC0

사람 캐릭터를 쓰지 않는다. **조립식 도형 캐릭터**를 쓴다.

| 용도 | 팩 | 사용 | 규격 |
|---|---|---|---|
| 캐릭터 | Shape Characters (1.0) | 104 파일 | 80×80px · 몸통+얼굴+손 조립 |
| 서고·가구 | Isometric Miniature Library (2.1) | 22종 × 4방향 = 88 파일 | 256×512px · 정투영 |
| 바닥·벽 | Isometric Miniature Prototype | 7종 × 4방향 = 28 파일 | 256×512px · 정투영 |

합계 **220 파일 · 1.3MB**. 라이선스는 전부 **CC0 1.0** — 상업적 사용 자유, 저작자 표시 의무 없음. 제작자 요청에 따라 `web/assets/CREDITS.md`에 자발적으로 표기한다.

#### 도형 캐릭터를 고른 이유

1. **주제가 성격 유형론 비판이다.** 사람 캐릭터를 쓰면 "이 캐릭터는 무슨 유형처럼 생겼나" 같은 불필요한 해석이 붙는다. 도형은 그 문제가 원천적으로 없다.
2. **부품이 분리돼 있어 상태를 그림으로 말할 수 있다.** 4.2절의 번역 규칙이 그대로 구현된다.
3. **방향 문제를 우회한다.** 2D 아이소메트릭 사람 캐릭터는 CC0로 구하기 어렵다(조사 결과 Kenney·OpenGameArt·itch.io 모두 부적합). 도형은 눈동자 방향으로 시선을 표현해 4방향 스프라이트 없이 해결한다.

## 6. 평가 지표 — 계기판

정답표도 판정 모델도 쓰지 않는다. **만들어진 글과 실제로 읽은 문서만** 본다.

| 지표 | 계산 | 어느 장치의 계기 | 종류 |
|---|---|---|---|
| 근거율 | 문장 중 «문서명» 붙은 비율 | 깊이 · 재위임 | 잣대 |
| **인용 0곳 절 수** | `sum(1 for x in 절 if not x["인용"])` | **절 단위 근거 구멍** | **그물** |
| 허위 인용 | 읽지 않은 문서를 인용했나 | 경보 — 0이 아니면 탈락 | 그물 |
| **출처 불일치** | 인용 문서 원문에 그 문장의 고유명사·연도가 실제로 있나 | **인용의 타당성** | 잣대 (관찰 중) |
| 읽고 안 쓴 문서 | 읽었으나 보고서에 미등장 | 배정 품질 | 잣대 |
| 최다 문서 편중 | 인용이 한 문서에 몰린 비율 | 배정 · 구역 | 잣대 |
| 중복률 | 같은 문서를 두 절 이상이 읽음 | 구역 | 잣대 |
| 격리율 | 코디네이터가 본 글자 ÷ 팀 전체 | 격리 — 한 자릿수여야 정상 | 잣대 |

**「인용 0곳 절 수」를 추가한 이유** — 보고서 전체 근거율이 60%여도, 네 절 중 한 절이 0곳이면 그 절은 통째로 근거 없는 글이다. 전체 평균에 묻혀 안 보인다. 우리 주제가 "근거 없는 주장을 검증하는 것"이므로, **절 단위로 구멍을 잡는 그물**이 반드시 필요하다. (14강 더해보기 2번)

**「출처 불일치」를 추가한 이유** — 근거율은 «»가 **붙어 있는지**만 잰다. 붙은 근거가 **맞는지**는 재지 못한다. 실제로 «16PF Questionnaire» 원문에 한 번도 나오지 않는 아담 그랜트 발언에 그 문서가 인용된 사례를 잡았다(2026-09-22 실측). 판정 모델은 쓰지 않는다. 문장 속 영문 고유명사·4자리 연도가 인용된 문서 원문에 글자 그대로 있는지 대조할 뿐이다.

> **한계** — 한국어 표기만 있고 영문 병기가 없는 이름은 놓친다. 그래서 그물이 아니라 잣대로 둔다.

### 6.1 그물과 잣대 분리

- **그물(자동 탈락 기준)**: 허위 인용 > 0 · 인용 0곳 절 > 0 · 편중 > 50%
- **잣대(순위 비교)**: 근거율 · 출처 불일치 · 읽고 안 쓴 문서 · 중복률 · 격리율
- 그물을 통과한 것만 사람이 읽고 고른다 (16강)

### 7.1 질문 3개 (성격이 다른 것으로)

### 7.2 설정 4개

| 이름 | 끄는 것 | 무엇을 보려는가 |
|---|---|---|
| 기본 | — | 기준선 |
| 배정·구역 끔 | `배정`, `구역` | 중복률·편중이 뛰는가 |

| 재위임 끔 | `재위임` | 근거율이 떨어지는가 |

## 13. 구현 실측 기록 (2026-09-22)

계획서가 예측한 것과 **실제로 돌려 보니 달랐던 것**을 남긴다. 추측으로 고치지 않기 위해서다.

### 13.1 원고 프롬프트 A/B — 규칙보다 본보기

같은 메모 4세트로 원고 작성 프롬프트만 바꿔 2회씩 측정했다.

| 변형 | 근거율 (1회) | (2회) | 요지 |
|---|---|---|---|
| V0 현행 | 27.0% | 29.4% | "문장마다 «문서명»을 붙인다" 한 줄 |
| V1 인용 강제 | 17.9% | 22.2% | ★로 강조 + 자기 점검 요구 |
| **V2 한 문장 한 사실** | **96.7%** | **100.0%** | **잘된 문장 2개 · 잘못된 문장 2개를 본보기로 제시** |

**규칙을 강하게 쓴 V1이 오히려 나빴다.** 모델은 지시의 강도가 아니라 **본보기**에 반응했다. V2 채택.

부작용: 인용을 강제하니 모델이 자기 추론 문장에도 «»를 갖다 붙였다. 금지 예시를 프롬프트에 그대로 넣어도 재발했다. 프롬프트로는 완전히 못 막는다 → **지표(출처 불일치)로 잡는다**.

### 13.2 잡은 버그 2개 — 둘 다 구현 중 만든 것

| 버그 | 증상 | 원인 | 수정 |
|---|---|---|---|
| 메모 유실 | 재위임을 거친 절만 근거율 25% | 2바퀴 조사관이 1바퀴 메모를 못 물려받아, 1바퀴에 읽은 문서를 인용할 자격을 잃었다 | 메모 본문을 상태에 보존해 다음 바퀴로 넘긴다 |
| **오귀속 유발** | 아담 그랜트 발언에 «16PF Questionnaire» 인용 | 허위 인용 교정 프롬프트가 "허용 목록 문서로 **근거를 바꿔 달라**"고 지시했다 | "통째로 **지워라**. 다른 문서 이름으로 바꿔 달지 마라" |

두 번째가 더 나쁘다. **허위 인용 0이 지표를 속여 만든 값이었다.** 원문 대조로 확인했다 — «16PF Questionnaire»에 "Grant" 0회, «Myers–Briggs Type Indicator»에 3회.

교훈: **지표를 만족시키라고 시키면 모델은 지표를 만족시킨다.** 지표가 재지 못하는 쪽으로.

### 13.3 재위임은 범인이 아니었다

"재위임 절의 근거율이 낮다"는 관찰에서 "재위임이 인용 규칙을 희석한다"고 의심했으나, 같은 직전 원고를 주고 A/B 한 결과 **현행·개선 모두 100%** 였다. 재위임 절이 나빠 보인 것은 **선택 편향**이다 — 점검이 원래 부실한 절만 되돌려 보내기 때문이다. 진짜 원인은 13.2의 메모 유실이었다.

### 13.4 기준선 (기본 설정 · 재현 3회)

```
근거율 73.3 ~ 96.4% (평균 82.7%)   인용0곳절 0   허위인용 0   출처불일치 0
격리율 1.9%   중복률 15~31%   보고서 2,520 ~ 2,770자
21~26 호출 · 입력 약 16만 토큰 · 편당 ₩34~46 · 30~40초
```

격리율 1.9%는 계획서가 요구한 "한 자릿수"를 만족한다. 컨텍스트 격리는 단일 조사관 기준 **원문 94,675자 → 메모 631자 (0.7%)**.

### 13.5 아직 안 고친 것 (절제 실험이 측정할 대상)

- **「관계」 서고 0건** — `Assortative mating`에 6회 모두 아무도 닿지 못했다. 계획서 2.5절 예측대로.
  → **14.3에서 뒤집혔다.** 질문을 「관계」형으로 바꾸자 네 설정 모두 닿았다. 배정의 실패가 아니라 **질문 어휘의 문제**였다.
- **`cap=60000` 잘림** — `Carl Jung`(93K)·`Big Five`(91K)가 자주 "관련 없음" 판정을 받는다. 잘림이 원인인지 미확인.
- **절 제목 중복** — 기획 노드가 같은 제목을 두 번 낸 사례 1건.
- **구역 분할의 대가** — 시작 문서만 나누고 프런티어는 안 나눈다. 두 절이 같은 문서를 각각 읽고 둘 다 "관련 없음" 판정한 사례가 있다.

## 14. 절제 실험 실측 (2026-09-22)

7장의 계획을 실제로 돌린 결과다. 생성기는 `pipeline/record.py`, 산물은 `runs/{질문}-{설정}.json` 12편.
**총 ₩356 · 4분 15초 · 그물 통과 10 / 탈락 2.**

### 14.1 근거율 12칸

| 질문 | 기본 | 배정·구역끔 | 역할끔 | 재위임끔 |
|---|---|---|---|---|
| **단일** (바넘 효과) | 0.57 | 0.78 ❌허위인용 | 0.55 | 0.59 |
| **다갈래** (MBTI 궁합) | 0.93 | 0.75 | **1.00** | 0.82 ❌인용0곳절 |
| **관계** (유유상종) | 0.85 | 0.79 | 0.90 | 0.91 |

❌는 그물 탈락. 탈락 2편은 사람이 읽을 후보에서 자동으로 빠진다(6.1절).

### 14.2 기대대로였던 것 — 「단일 질문은 나누면 손해」

단일 질문은 근거율 0.55~0.59로 세 질문 중 최저이고, 중복률 0.38로 최고다.
답이 한 문서에 몰려 있는데 4절로 쪼개니 **같은 문서를 네 번 읽는다**.
배정·구역을 끄면 중복률이 0.38 → 0.50, 편중이 0.29 → 0.43으로 뛴다 —
7.2절이 예측한 그대로다. 다만 **이 상승은 단일 질문에서만 나타났고**,
다갈래·관계에서는 오히려 내려갔다.

### 14.3 어긋난 것 ① — 고립 문서 도달에 변별력이 없었다

7.1절은 「관계」 질문을 **배정 품질 시험**으로 설계했다. 고립 문서 `Assortative mating`은
링크로 닿을 수 없으니, 배정이 제대로 일해야만 도달한다는 가정이었다.

실측은 **네 설정 모두 도달**이었다. 배정·구역을 끈 편까지 닿았고, 넷 다 보고서에 인용했다.
배정을 끄고도 닿는다면 그 도달은 배정이 한 일이 아니다.
질문 자체의 어휘가 문서 제목과 가까워서 검색이 곧장 집어 온 것으로 보인다.

→ **이 질문은 배정 품질을 재지 못한다.** 13.5의 「관계 서고 0건」이 배정의 실패로 보였던 것도
같은 이유의 뒷면이었다: 문제는 배정이 아니라 **질문이 무엇을 부르느냐**였다.
배정 품질을 재려면 제목과 어휘가 겹치지 않는 고립 문서를 따로 골라야 한다.

### 14.4 어긋난 것 ② — 역할을 끈 쪽이 더 나은 경우가 2/3

7.2절은 역할 끔에 대해 "**정말 차이가 없는가**(17강 결론 재현)"를 물었다.
실측은 차이 없음을 넘어 **끈 쪽이 나은 방향**으로 나왔다 — 다갈래 1.00 vs 0.93, 관계 0.90 vs 0.85.
기본이 이긴 것은 단일(0.57 vs 0.55)뿐이고 그 차이는 0.02다.

**단, 이것은 각 칸이 1회 실행인 n=3 관찰이다.** 13.4의 기준선이 같은 설정에서
73.3~96.4%로 흔들렸음을 기억해야 한다. 그 폭이면 0.93과 1.00은 구별되지 않는다.
**"역할을 끄는 게 낫다"고 쓰면 안 된다.** 지금 말할 수 있는 것은
"역할을 켜서 좋아졌다는 증거가 이 12편에 없다"까지다.

→ 5장 시각화와 배포 콘텐츠의 문구는 여기에 맞춘다. 단정하려면 칸마다 3회씩 재야 한다(₩1,100 · 15분).

### 14.5 남은 숙제

- **역할 축 반복 측정** — 위 이유로 n=1은 결론을 못 낸다.
- **배정 품질을 잴 질문 다시 설계** — 제목 어휘가 겹치지 않는 고립 문서 기준으로.
- **탈락 2편의 원인 확인** — 단일·배정구역끔의 허위 인용 1건, 다갈래·재위임끔의 인용 0곳 절 1건.
  재위임을 끄면 근거가 빈 절이 생긴다는 7.2절 가설과 방향이 맞지만, 역시 1건이다.
